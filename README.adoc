== Introduction

This Dynamic Discovery Client is a web service client designed to lookup and retrieve metadata of Participants hosted under any compliant Service Metadata Publishers (SMP). This web service client can be used with SMPs that implement the SMP profile based on the OASIS SMP 1.0 and  OASIS SMP 2.0 specifications.

NOTE: Since 3+ version, the client is based on Jakarta EE 10+ XML binding API and is build with target java level 11.


=== Purpose of this document

This page provides a brief description of how to use this web service client to connect to a Service Metadata Publisher using CNAME or NAPTR record to find out and retrieve Receiver Recipient Metadata.

== Setting up parameters

The DynamicDiscoveryBuilder class provides 6 interfaces and theirs default implementations, however, the user is free to use customized implementations to fit other needs.


=== Interfaces and implementations

**IPublisherLocator**

This interface is responsible for managing the lookup algorithm and providing the URL or URI for the request. By default it provides the implementation **eu.europa.ec.dynamicdiscovery.core.locator.impl.DefaultBDXRLocator** for looking up NAPTR or CNAME records.
Alternative is the **eu.europa.ec.dynamicdiscovery.core.fetcher.impl.StaticMapMetadataLocator.** for preconfigured/default SMP URI.

**IDocumentFetcher**

This interface is responsible for fetching the response from the request. By default it provides the implementation **eu.europa.ec.dynamicdiscovery.core.fetcher.impl.DefaultURLFetcher.**

**IDNSLookup**

This interface is responsible for looking up the participant identifier. By default it provides the implementation **eu.europa.ec.dynamicdiscovery.core.locator.dns.impl.DefaultDNSLookup.**

**IDocumentRequestProvider**

This interface is responsible for resolving URIs for participant identifier metadata. By default it provides the implementation **eu.europa.ec.dynamicdiscovery.core.provider.impl.DefaultProvider.**

**ISMPDocumentReader**

This interface is responsible for parsing the response according to the **IExtensions**. By default it provides the implementation **eu.europa.ec.dynamicdiscovery.core.reader.impl.DefaultBDXRReader.** with Oasis SMP 1.0 and  Oasis SMP 2.0 extensions.

**IExtensions**

This interface contains a list of **IObjectReader** for the extension. The purpose of the implementation is to provide necessary methods for DDDC client to ready various document and to produce standard internal SMP objects.  By default DDC contains

* **eu.europa.ec.dynamicdiscovery.core.extension.impl.OasisSMP10Extension** implementation of the Oasis SMP 1.0 standard
* **eu.europa.ec.dynamicdiscovery.core.extension.impl.OasisSMP20Extension** implementation of the Oasis SMP 2.0 standard


**IObjectReader**

Reads the XML Document and generates the specified output object.



**ISignatureValidator**

This interface is responsible for verifying the signature of the response according to the XSD and is used by the abstract class **eu.europa.ec.dynamicdiscovery.core.security.AbstractSignatureValidator**, all the implementations must extend this abstract class.
By default the implementation **eu.europa.ec.dynamicdiscovery.core.security.impl.DefaultSignatureValidator** is provided.

=== Locator configuration

The DDC has two  Locator implementations.
- **DefaultBDXRLocator** lookup's the authoritative domain DNS given as a constructor parameter.
- **StaticMapMetadataLocator** returns SMP's  URI based on preconfigured party identifier and URI mapping. If the party identifier is not found in the mapping, it returns the default URI.

==== BDXL DNS Locator configuration (DefaultBDXRLocator)

===== Example: Basic discovery with one top domain
Configuration of the DefaultBDXRLocator to resolve SMP's URI based on PartyIdentifier one top dns domain
[source,java]
----
DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
        .publisherLocator(new DefaultBDXRLocator.Builder().addTopDnsDomain("acc.edelivery.tech.ec.europa.eu").build())
        .documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(CommonUtil.loadTrustStore("truststore/truststoreForTrustedCertificate.ts"))))
        .build();
----
===== Example: Basic discovery with a list of top domain
Configuration of the DefaultBDXRLocator to resolve SMP's URI based on PartyIdentifier with list top dns domains
[source,java]
----
DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
        .publisherLocator(new DefaultBDXRLocator.Builder()
                .addTopDnsDomain("acc.edelivery.tech.ec.europa.eu")
                .addTopDnsDomain("acc.second.domain.com")
                .build())
        .documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(CommonUtil.loadTrustStore("truststore/truststoreForTrustedCertificate.ts"))))
        .build();
----

===== Example: Basic discovery with one top domain with only NAPTR lookup type
Configuration of the DefaultBDXRLocator to resolve SMP's URI based on PartyIdentifier one top dns domain.
The client will use only NAPTR DNS records with default service "Meta:SMP".
[source,java]
----
DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
        .publisherLocator(new DefaultBDXRLocator.Builder()
                .addTopDnsDomain("acc.edelivery.tech.ec.europa.eu")
                .addDnsLookupTypes(Collections.singletonList(DNSLookupType.NAPTR))
                .build())
        .documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(CommonUtil.loadTrustStore("truststore/truststoreForTrustedCertificate.ts"))))
        .build();
----

===== Example: Basic discovery with one top domain with only NAPTR and meta:cppa3 service
Configuration of the DefaultBDXRLocator to resolve SMP's URI based on PartyIdentifier one top dns domain.
The client will use only NAPTR DNS records with service "meta:cppa3" (Default is Meta:SMP).
[source,java]
----
DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
        .publisherLocator(new DefaultBDXRLocator.Builder()
                .addTopDnsDomain("acc.edelivery.tech.ec.europa.eu")
                .addDnsLookupType(DNSLookupType.NAPTR)
                .dnsLookup(new DefaultDNSLookup.Builder()
                        .addRequiredNaptrService("meta:cppa3")
                        .build())
                .build())
        .documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(CommonUtil.loadTrustStore("truststore/truststoreForTrustedCertificate.ts"))))
        .build();
----

===== Example: Basic discovery with one top domain with only NAPTR and meta:cppa3 service and only urls with https: schema
Configuration of the DefaultBDXRLocator to resolve SMP's URI based on PartyIdentifier one top dns domain.
The client will use only NAPTR DNS records with service "meta:cppa3" (Default is Meta:SMP) and will return only results with URL schema: "https:".
[source,java]
----
DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
        .publisherLocator(new DefaultBDXRLocator.Builder()
                .addTopDnsDomain("acc.edelivery.tech.ec.europa.eu")
                .addDnsLookupType(DNSLookupType.NAPTR)
                .dnsLookup(new DefaultDNSLookup.Builder()
                        .addRequiredNaptrService("meta:cppa3")
                        .addRequiredNaptrURLSchema("https:")
                        .build())
                .build())
        .documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(CommonUtil.loadTrustStore("truststore/truststoreForTrustedCertificate.ts"))))
        .build();
----

===== Example: Basic discovery with custom participant formatter
Configuration of the DefaultBDXRLocator to resolve SMP's URI based on custom PartyIdentifier types. By default ebCoreParty Identifier type and Peppol Party identifier types are registered.

The DefaultBDXRLocator will format/normalize the PartyIdentifier before lookup according to custom FormatterType

[source,java]
----
// Use template formatter or create own formatter type
FormatterType customFormatter = new TemplateFormatterType(Pattern.compile("^(?i)mailto.*$"),
                "${scheme}-->${identifier}","${identifier}",
                Pattern.compile("^(?i)\\s*(-->)?(?<scheme>mailto)-->(?<identifier>.+)?\\s*$"),
                DNSLookupFormatType.SCHEMA_AFTER_HASH);

// register formatter to DefaultBDXRLocator
DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
        .publisherLocator(new DefaultBDXRLocator.Builder()
                .addTopDnsDomain("acc.edelivery.tech.ec.europa.eu")
                .addFormatterType(customFormatter)
                .dnsLookup(new DefaultDNSLookup.Builder()
                        .addRequiredNaptrService("meta:cppa3")
                        .addRequiredNaptrURLSchema("https:")
                        .build())
                .build())
        .documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(CommonUtil.loadTrustStore("truststore/truststoreForTrustedCertificate.ts"))))
        .build();
----

===== Example: Static Metadata Locator with single SMP url
Example of how to configure with StaticMapMetadataLocator. The DDC will always fetch the party identifier's service metadata data from the give URI: " http://localhost:8090/cipa-smp-full-webapp/"
[source,java]
----
DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
    .publisherLocator(new StaticMapMetadataLocator(new URI("http://localhost:8090/cipa-smp-full-webapp/")))
    .documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(truststore)))
    .build();
----
===== Example: Static Metadata Locator with List of SMP urls
Example of how to configure with StaticMapMetadataLocator with mapping. The DDC will try to looup party identifier mapping URI. If Party identifier is not found in the mapping, it will fetch the party identifier's service metadata data from the give URI: " http://localhost:8090/cipa-smp-full-webapp/"

[source,java]
----
URI defaultURI =new URI("http://localhost:8090/cipa-smp-full-webapp/");
Map<ParticipantIdentifier, URI> mapExceptions = new HashMap<>();
mapExceptions.put(new ParticipantIdentifier("testId-01", "testScheme"), new URI("http://test-01/smp/"));
mapExceptions.put(new ParticipantIdentifier("testId-02", "testScheme"), new URI("http://test-02/smp/"));

DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
    .publisherLocator(new StaticMapMetadataLocator(defaultURI, mapExceptions))
    .documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(truststore)))
    .build();
----

=== Proxy configuration

By default **eu.europa.ec.dynamicdiscovery.core.fetcher.impl.DefaultURLFetcher** does not use proxy configuration. In order to use proxy, an instance of the class **eu.europa.ec.dynamicdiscovery.core.security.impl.DefaultProxy** must be configured and passed by parameter as follows:

Example:
[source,java]
----
DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder().fetcher(new DefaultURLFetcher(new DefaultProxy("127.0.0.1", 8000, "user", "password"))).build();
----

=== Signature Truststore configuration

In order to check if the certificate extracted from the signed response is trusted even if the signature is valid, a truststore must be passed by parameter to the Signature Validator implementation.A trusted certificate must be included in the truststore.

Example:
[source,java]
----
 KeyStore truststore = KeyStore.getInstance("JKS");
 truststore.load(new FileInputStream(Thread.currentThread().getContextClassLoader().getResource("example/truststore.ts").getFile()), null);

 DefaultSignatureValidator signatureValidator = new DefaultSignatureValidator(truststore);
----

=== Configure regular expression to validate signature certificate subject

Apart from validating response of signer certificates against the truststore, the Dynamic Discovery gives the possibility to add (optional) a regular expression to validate any certificate metadata related to the subject of the signer certificate.

In order to add this optional validation, please follow the steps below:
[source,java]
----
// Default Signature Validator with regex to check certificate subject

KeyStore truststore = KeyStore.getInstance("JKS");
truststore.load(new FileInputStream(Thread.currentThread().getContextClassLoader().getResource("example/truststore.ts").getFile()), null);

String regexSubjectValidation = "^CN=eDelivery_SMP_TEST_1.*$"
DefaultSignatureValidator signatureValidator = new DefaultSignatureValidator(truststore,regexSubjectValidation);

// Default Signature Validator

KeyStore truststore = KeyStore.getInstance("JKS");
truststore.load(new FileInputStream(Thread.currentThread().getContextClassLoader().getResource("example/truststore.ts").getFile()), null);

DefaultSignatureValidator signatureValidator = new DefaultSignatureValidator(truststore);
----

=== Configure only HTTPS  with mutual TLS authentication

Following example configures the default fetcher to allow retrieving SMP data only via https schema.

[source,java]
----
// load truststore
KeyStore clientTruststore = CommonUtil.loadKeystore("/truststore/tls-truststore.p12", KEYSTORE_TYPE, PASSWD);

// build DefaultURLFetcher
DefaultURLFetcher testInstance = new DefaultURLFetcher.Builder()
        .enableHttpScheme(false)
        .tlsTruststore(clientTruststore)
        .build();
----


=== Configure Default Fetcher HTTPS with mutual TLS authentication

Following example configures the default fetcher to use mutual TLS authentication when retrieving SMP data.
[source,java]
----
KeyStore clientKeystore = CommonUtil.loadKeystore("/truststore/server-keystore.p12", KEYSTORE_TYPE, PASSWD);
KeyStore clientTruststore = CommonUtil.loadKeystore("/truststore/tls-truststore.p12", KEYSTORE_TYPE, PASSWD);

DefaultURLFetcher testInstance = new DefaultURLFetcher.Builder()
        .enableHttpScheme(false)
        .tlsKeystore(clientKeystore, PASSWD.toCharArray())
        .tlsTruststore(clientTruststore)
        .build();
----

=== Configure Default Fetcher HTTPS with mutual TLS authentication and allowed algorithms

Following example configures the default fetcher with allowed TLS Cipher suites and TLS versions.
The cipher suits names and TLS versions are supported and defined by JCE provider or JAVA version standard names:

https://docs.oracle.com/en/java/javase/18/docs/specs/security/standard-names.html#sslcontext-algorithms

[source,java]
----
KeyStore clientKeystore = CommonUtil.loadKeystore("/truststore/server-keystore.p12", KEYSTORE_TYPE, PASSWD);
KeyStore clientTruststore = CommonUtil.loadKeystore("/truststore/tls-truststore.p12", KEYSTORE_TYPE, PASSWD);

DefaultURLFetcher testInstance = new DefaultURLFetcher.Builder()
        .enableHttpScheme(false)
        .tlsKeystore(clientKeystore, PASSWD.toCharArray())
        .tlsTruststore(clientTruststore)
        .tlsCipherSuites("TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA256", "TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384")
        .tlsVersions("TLSv1.2","TLSv1.3")
        .build();
----

== How to use the dynamic discovery client

The DynamicDiscoveryBuilder is responsible for creating a new instance of the Dynamic Discovery Client. By default, there are implementations for all core services provided by the tool however new customized implementations can be used by the user.

Default implementation example:
[source,java]
----
KeyStore truststore = KeyStore.getInstance("JKS");
truststore.load(new FileInputStream(Thread.currentThread().getContextClassLoader().getResource("example/truststore.ts").getFile()), null);

DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
.publisherLocator(new DefaultBDXRLocator("ehealth.acc.edelivery.tech.ec.europa.eu"))
.documentReader(new DefaultBDXRReader(new DefaultSignatureValidator(truststore)))
.build();

ParticipantIdentifier participantIdentifier = new ParticipantIdentifier("9925:0367302178", "iso6523-actorid-upis");
----

=== Get list of service group documents
[source,java]
----
SMPServiceGroup serviceGroup = smpClient.getServiceGroup(participantIdentifier);
List<DocumentIdentifier> documents = serviceGroup.getDocumentIdentifiers();
----

===  Get document service metadata
[source,java]
----
SMPServiceMetadata serviceMetadata = smpClient.getServiceMetadata(participantIdentifier, new SMPDocumentIdentifier("urn::epsos:services== epsos-21", "epsos-docid-qns"));
SMPEndpoint endpoint = serviceMetadata.getEndpoints().get(0);
----


=== Certificate Pinning/Whitelisting: A Security Technique for Validating Digital Certificates

A SMP Certificate Pinning/whitelisting is a security mechanism that integrates into dynamic discovery infrastructure,
validating expected digital certificates against predetermined service parameters (e.g., participant identifiers,
document identifiers). This service enables dynamic receiver to whitelist/pinned certificates, ensuring that only registered
certificates can participate in secure message exchange.

[source,java]
----

   X509Certificate certificateToValidate = ... ;
   String expecteDertificateCode = null;
   try {
        smpClient.certificateExists(certificateToValidate, expecteDertificateCode,
                resourceIdentifier, subresourceIdentifier,
                processIdentifierIdentifier, transportProfile);
    } catch (DDCCertificateNotFoundException e) {
        LOG.error("Certificate in not trusted for given parameters!", e);
    } catch (TechnicalException e) {
        LOG.error("The certificate can not be validated!", e);
    }
----

== Customized implementation example

Please replace classes starting with **"Customized"** by implementations extended from the aforementioned interfaces.It is not mandatory to have implementations for all the components (Locator, Reader, DNSLookup, Provider, Fetcher)

[source,java]
----
KeyStore truststore = KeyStore.getInstance("PKCS12");
truststore.load(new FileInputStream(Thread.currentThread().getContextClassLoader().getResource("example/truststore.ts").getFile()), null);

DynamicDiscoveryService smpClient = new DynamicDiscoveryService.Builder()
        .publisherLocator(new CustomizedBDXRLocator("acc.edelivery.tech.ec.europa.eu", new CustomizedDNSLookup()))
        .documentReader(new CustomizedBdxrReader(new CustomizedSignatureValidator(truststore)))
        .documentRequestProvider(new CustomizedProvider())
        .documentFetcher(new CustomizedURLFetcher(new CustomizedProxyConfiguration("127.0.0.1", 8000, "user", "password")))
        .build();
SMPParticipantIdentifier participantIdentifier = new SMPParticipantIdentifier("9925:0367302178", "iso6523-actorid-upis");
----
